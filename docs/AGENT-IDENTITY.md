# 에이전트 식별 규칙

## 핵심 개념

| 개념 | 의미 | 기록 위치 |
|---|---|---|
| **에이전트 식별자** | 실제로 작업한 AI. 이 저장소의 규칙으로 정의 | 본문, 커밋 trailer, 라벨 |
| **GitHub 계정 신원** | GitHub이 인증한 사용자 | GitHub이 자동 기록 |

두 개념은 다르다. 초기에는 모든 에이전트가 하나의 GitHub 계정을 쓰므로, GitHub UI의 작성자만으로는 누가 작업했는지 알 수 없다.
그래서 식별자를 **직접 적는다.** 식별자는 자기 신고이며 GitHub이 보증하지 않는다.

## 식별자 형식

`AI-<ROLE>-<NN>`

| ROLE | 역할 |
|---|---|
| PM | 프로젝트 관리 |
| DEV | 개발 |
| RES | 연구, 분석 |
| DOC | 문서 |
| QA | 검증, 리뷰 |
| BOOTSTRAP | 초기 구축 (일회성) |

예: `AI-DEV-01`, `AI-QA-01`. 역할은 프로젝트 필요에 따라 추가한다. 사람은 `HUMAN-<이름>` 형식을 쓴다.

## 어디에 쓰는가

**Issue, PR 본문 마지막 줄**

```
Agent: AI-DEV-01
```

이슈 폼(`.github/ISSUE_TEMPLATE/`)은 줄 단위 표기를 만들 수 없으므로 필수 입력 항목 `Agent`가 본문에 `### Agent` 섹션으로 기록된다. 이 섹션이 이슈의 `Agent:` 줄을 대신한다.

**커밋 메시지 trailer**

```
Agent: AI-DEV-01
```

**Issue, PR 댓글 첫 줄**

```
**[AI-QA-01]** 리뷰 결과: 통과
```

**라벨:** 식별자에서 `AI-`를 떼고 소문자로 쓴 `agent:<role>-<nn>` (예: `AI-DEV-01` → `agent:dev-01`, `AI-BOOTSTRAP-01` → `agent:bootstrap-01`). 사람은 `agent:human`. 담당자 표시용이다. 새 식별자를 쓰기 전에 해당 라벨을 만든다.

## 선택 기록

추적이 필요하면 다음을 PR 본문에 추가한다.

```
Model: <모델명>
Runtime: <실행 환경>
Session: <세션 또는 실행 ID>
```

## 사람과 AI의 구분

- AI가 한 작업은 반드시 `Agent:` 줄이 있다.
- `Agent:` 줄이 없고 `HUMAN-` 표기가 있으면 사람이 한 작업이다.
- 둘 다 없으면 출처 불명으로 본다. 리뷰 시 지적한다.

## 한계와 확장

- 자기 신고 방식이라 위조할 수 있다. 신뢰 경계가 필요하면 GitHub Apps로 에이전트별 인증 주체를 분리한다. (장기 과제, 필요해지면 `type:decision` Issue로 제안)
- 같은 계정이므로 에이전트가 쓴 PR을 GitHub의 정식 Approve로 승인할 수 없다.
